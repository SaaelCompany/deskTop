# Переключение рабочего стола при потере сети

Программа для Windows следит за доступом в интернет и за общей папкой рабочего стола. Когда связь пропадает, папка «Рабочий стол» текущего пользователя переключается на локальный диск. Когда связь возвращается, снова включается сетевой путь.

Пока сеть есть, ярлыки (`.lnk` и `.url`) копируются с общей папки в локальную. После переключения на столе остаются эти копии.

## Когда это нужно

Общий рабочий стол в домене обычно задан перенаправлением папки: у пользователя в профиле записан путь вида `\\сервер\общая\Desktop`. Проводник читает ярлыки прямо с сервера. Если сервер или интернет недоступны, ярлыки исчезают. У Windows нет запасного локального пути. Эта программа подставляет его сама.

Путь хранится в профиле пользователя (`HKCU`), в значении `Desktop` раздела `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders`. Если перенаправление уже создало значение `{B4BFCC3A-DB2C-424C-B029-7FE99A87C641}`, обновляется и оно. Запускайте программу в сеансе этого пользователя: служба от имени SYSTEM пишет в другой профиль, и стол не меняется.

Обычному пользователю права администратора не нужны. Политика сама записывает сетевой путь, и у разных пользователей он может отличаться. `NetworkDesktopPath` оставьте пустым: программа читает путь из профиля. Пока стол сетевой, берётся текущий UNC. После переключения на локальную папку запоминается последний путь политики, чтобы вернуть именно его. Если политика сменит путь, следующее открытие сетевого стола подхватит новый UNC. Явный UNC в `config.json` нужен только когда путь надо зафиксировать.

## Что происходит при сбое

1. Каждые 15 секунд проверяется интернет и общая папка.
2. Две проверки подряд без связи переключают рабочий стол на локальную папку и перезапускают Проводник. Окна Проводника закрываются, остальные программы остаются.
3. Три успешные проверки подряд возвращают сетевой путь.
4. Если групповая политика во время сбоя снова записывает сетевой путь, программа возвращает локальный.
5. Появляется уведомление. Файлы, созданные на локальном столе во время сбоя, остаются в локальной папке этого компьютера.

По умолчанию переключение срабатывает, если нет интернета или недоступна общая папка (`Trigger` = `InternetOrShare`). Локальный стол включается и тогда, когда файловый сервер недоступен, а проверка интернета ещё отвечает. В `config.json` можно выбрать другое условие:

| Trigger | Когда включается локальный стол |
| --- | --- |
| `InternetOrShare` | Нет интернета или недоступна общая папка |
| `Internet` | Только когда нет интернета |
| `Share` | Только когда недоступна общая папка |

Проверка интернета состоит из двух частей. Сначала программа спрашивает статус сети Windows. Если Windows не видит интернет, выполняется HTTP-запрос (по умолчанию `http://www.msftconnecttest.com/connecttest.txt`) через системный прокси — это нужно в сетях, где статус Windows ошибочно показывает «нет интернета». Общая папка проверяется подключением к порту 445 сервера и чтением каталога. Зависшее обращение к шаре не блокирует следующие циклы.

## Установка

Нужны Windows 10, Windows 11 или Windows Server с рабочим столом и Windows PowerShell 5.1. Установка в автозагрузку текущего пользователя прав администратора не требует.

Администратор один раз кладёт папку на локальный диск, например в `C:\Tools\DesktopSwitch`, и даёт пользователям чтение. Пользователь запускает установщик у себя. Если оставить программу на той же шаре, что и рабочий стол, при обрыве сети она не запустится.

```powershell
cd C:\Tools\DesktopSwitch
copy config.example.json config.json
notepad config.json
```

В `config.json`:

- `Enabled` — `true`.
- `NetworkDesktopPath` оставьте пустым, чтобы следовать политике.
- `Widget.ServiceDesk` — куда уходит заявка: `Auto`, `Webhook` или `Jira`. По умолчанию `Auto`.
- `Widget.ServiceDeskApiUrl` — универсальный адрес любого helpdesk. Сюда уходит POST с JSON.
- `Widget.ServiceDeskUrl` — страница портала. В адресе можно использовать `{login}` и `{computer}`.
- `Widget.Categories` — пункты списка «Категория» для универсальной отправки.
- `Widget.Projects` — проекты, из которых сотрудник выбирает, куда писать заявку. Пустой список означает один приёмник: все заявки идут на `ServiceDeskApiUrl`.
- `Widget.JiraBaseUrl` — адрес Jira Server или Data Center. Используется, когда `ServiceDesk` равен `Jira`, либо в режиме `Auto`, если адрес API пуст и заполнен только этот адрес.
- `Widget.NewsUrl` — лента новостей и технических работ, JSON или RSS. Новости берутся только из этого адреса.
- `LocalDesktopPath` можно не менять. По умолчанию это `%LOCALAPPDATA%\DesktopSwitch\LocalDesktop`, отдельная папка. Так программа не попадает в junction, которым перенаправление иногда подменяет `%USERPROFILE%\Desktop`.

Узнать текущий сетевой путь, пока стол ещё открывается:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\DesktopSwitch.ps1 -Status
```

Перед включением можно посмотреть решение без записи в реестр:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\DesktopSwitch.ps1 -Once -WhatIf
```

Автозагрузка текущего пользователя, без повышения прав:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-DesktopSwitch.ps1
```

Общая автозагрузка всего компьютера требует администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-DesktopSwitch.ps1 -AllUsers
```

Установщик кладёт `DesktopSwitch.vbs` в автозагрузку, останавливает старый монитор и запускает новый. Ключ `-ScheduledTask` дополнительно создаёт задачу на вход пользователя. Повторный запуск установщика применяет изменённый `config.json`.

## Пакет SCCM

Все настройки кладутся в пакет заранее. В источнике приложения рядом со скриптами должен лежать готовый `config.json`: `Enabled` равен `true`, адрес helpdesk, проекты, категории и лента новостей уже заполнены. `NetworkDesktopPath` оставьте пустым: путь общего стола у каждого пользователя свой и читается из политики. Отдельная настройка на компьютере после установки не нужна.

Программа установки SCCM выполняется от SYSTEM:

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-DesktopSwitch.ps1 -InstallDir "%ProgramFiles%\DesktopSwitch" -AllUsers
```

`-InstallDir` копирует пакет в постоянную папку. Ярлык автозагрузки указывает на неё, а не на кэш SCCM. Учётная запись SYSTEM включает автозапуск для всех пользователей и не запускает монитор в своём сеансе: окно и переключение стола появляются при входе сотрудника. Повторная установка заменяет и файлы, и `config.json`.

Обнаружение: существует `%ProgramFiles%\DesktopSwitch\DesktopSwitch.ps1`.

Удаление:

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "%ProgramFiles%\DesktopSwitch\Uninstall-DesktopSwitch.ps1" -AllUsers -InstallDir "%ProgramFiles%\DesktopSwitch"
```

Папка программы удаляется. Журналы в `%LOCALAPPDATA%\DesktopSwitch` и локальные копии ярлыков остаются. Пользователям достаточно чтения папки установки: общий ключ helpdesk в `config.json` они менять не должны.

Журнал каждого пользователя: `%LOCALAPPDATA%\DesktopSwitch\desktop-switch.log`. Двойной щелчок по `Show-DesktopSwitchStatus.cmd` показывает текущее состояние.

## Полезные параметры

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `CheckIntervalSeconds` | 15 | Пауза между проверками. Меньше 5 секунд программа поднимет до 5 |
| `FailuresBeforeSwitch` | 2 | Сколько сбоев подряд нужно для перехода на локальный стол |
| `SuccessesBeforeRestore` | 3 | Сколько успешных проверок подряд нужно, чтобы вернуть сетевой стол |
| `RestoreWhenOnline` | true | Возвращать сетевой путь после восстановления связи |
| `RestartExplorer` | true | Перезапускать Проводник, иначе новый путь виден только после повторного входа |
| `NotifyUser` | true | Показывать уведомление о смене стола, новостях и работах |
| `Widget.Enabled` | true | Круглая кнопка в углу экрана. `false` оставляет только фоновый монитор |
| `Widget.Icon` | пусто | Картинка внутри круглой кнопки: png или ico. Путь абсолютный либо относительно папки `config.json`, затем папки скрипта. Пустое значение оставляет значок чата. Файл читается при запуске |
| `Widget.Color` | пусто | Цвет круглой кнопки: `#1F6B4A` или с прозрачностью `#1F6B4A80` (последние две цифры — альфа). Пустое значение оставляет синий `#2F6BFF` |
| `Widget.Opacity` | 100 | Непрозрачность всей кнопки, от 0 до 100. 100 — сплошная, 40 — просвечивает. Дробь `0.4` значит то же, что 40. Если Opacity не задан, берётся альфа из `Color` |
| `Widget.NewsPollMinutes` | 10 | Как часто забирать ленту |
| `Widget.Corner` | BottomRight | Угол: BottomRight, BottomLeft, TopRight, TopLeft |
| `SyncShortcutsWhileOnline` | true | Копировать ярлыки с общей папки в локальную |
| `SyncExtensions` | `.lnk`, `.url` | Какие файлы копировать. Остальные файлы общей папки не копируются |
| `InternetCheck.ProbeUrls` | адрес проверки связи Microsoft | Свои адреса, например `https://intranet.company.local/health` |
| `InternetCheck.ExpectedProbeBody` | `Microsoft Connect Test` | Начало ответа. Для своего адреса очистите строку: тогда достаточно ответа 200 |
| `InternetCheck.UseWindowsConnectivity` | true | Учитывать статус сети Windows |

Если проверка не дала определённого ответа, режим не меняется, а счётчики успешных и неуспешных проверок сбрасываются.

## Пробный запуск без установки

В архиве `dist/DesktopSwitch-portable.zip` лежит папка для просмотра. Её распаковывают на локальный диск и запускают `Start-DesktopSwitch.vbs`. Установка и права администратора не нужны. В `config.json` этой копии `Preview` равен `true`: окно и значок у часов есть, рабочий стол не переключается. Чтобы включить переключение, поставьте `Preview` в `false` и `Enabled` в `true`.

Программа написана на Windows PowerShell 5.1. Отдельного файла формы нет: окно, кнопка и список новостей создаются кодом Windows Forms в `DesktopSwitch.Widget.ps1`. `DesktopSwitch.ps1` следит за сетью, `DesktopSwitch.Logic.ps1` принимает решение о переключении стола.

## Кнопка поддержки

В углу экрана остаётся круглая кнопка, как чат на сайте. По нажатию над ней открывается компактное окно со скруглёнными углами. Сначала открыта вкладка «Заявка». Повторное нажатие, крестик в шапке или Escape сворачивают его и не останавливают программу. Переключение стола от кнопки не зависит и происходит само. В шапке только название и состояние стола: логин и компьютер есть в полях заявки и второй раз не пишутся.

Окно само следует теме Windows, светлой или тёмной. Вкладки «Заявка» и «Новости» делят ширину окна пополам. Значок у часов есть всегда, пока виджет включён. В его меню пункт «Кнопка на экране» отмечен по умолчанию. Если снять галочку, круглая кнопка скрывается, а заявка, новости и выход остаются в этом меню. Пункт «Поверх всех окон» тоже включён по умолчанию: кнопка и окно лежат над другими программами. Если снять галочку, они остаются на рабочем столе и уходят назад, когда открыто другое окно. Оба выбора хранятся у пользователя в `state.json` и не входят в общий `config.json`.

Вкладка «Заявка» — одна форма для любого helpdesk: категория, тема и описание. В поле «Логин Windows» виден только пользователь, без домена. В заявку и в адрес портала по-прежнему уходит полный логин сеанса. Имя компьютера подставляется отдельно. Оба поля только для чтения. Если в адресе портала есть подстановки `{login}`, `{computer}`, `{project}` и `{projectId}`, они заменяются на значения из сеанса и выбранного проекта.

Куда уходит заявка, решает `Widget.ServiceDesk`:

- `Webhook` — универсальный путь. Программа отправляет POST JSON на `ServiceDeskApiUrl`. Так подключается любой helpdesk, у которого есть свой приём заявок, либо короткая прослойка перед ним. Тело запроса: `subject`, `body`, `category`, `project`, `projectId`, `user`, `computer`, `createdAt`. Список категорий задаётся в `Widget.Categories`. Если в `Widget.Projects` несколько проектов, сотрудник выбирает проект в окне, и в JSON уходят его название и код. Программа сама проект не назначает.
- `Jira` — встроенный адаптер Jira Service Management. Нужен `JiraBaseUrl`.
- `Auto` — если заполнен `ServiceDeskApiUrl`, выбирается универсальный POST, даже когда рядом указан адрес Jira. Jira включается сама только когда адрес API пуст, а `JiraBaseUrl` заполнен. Если задан только портал, кнопка открывает его.

Для Jira Server 8.21 и Jira Service Management 4.21.1 поставьте `ServiceDesk` в `Jira` и укажите `JiraBaseUrl`, например `https://jira.company.local`, без хвоста `/browse`. Это адрес Jira Server или Data Center. При открытии вкладки программа запрашивает `GET /rest/servicedeskapi/servicedesk` и показывает проекты helpdesk, которые видит эта учётная запись. После выбора проекта загружаются типы запросов. Кнопка «Отправить» создаёт клиентский запрос `POST /rest/servicedeskapi/request`. В описание дописываются логин Windows и имя компьютера. В случае успеха в окне появляется ключ заявки, например `ITHD-12`. Ссылка «Открыть портал» ведёт на `/servicedesk/customer/portals`, если свой адрес портала не задан.

Вход общий для обоих способов. Пустой `Widget.ServiceDeskToken` означает проверку Windows (Negotiate/NTLM) текущей учётной записи. Если сервер её не принимает, в `ServiceDeskToken` кладётся общий ключ: для Jira это личный токен доступа (PAT, Jira 8.14 и новее), для другого helpdesk — ключ его вебхука. Пароль сотрудника программа не хранит. Папку с `config.json` лучше оставить пользователям только для чтения.

Вкладка «Новости» показывает ленту. Технические работы отмечены янтарной точкой, обычные новости — точкой цвета текста. Лента — JSON, как в `examples/news.json`, либо RSS. У технических работ `"kind": "maintenance"` (или категория RSS со словом maintenance, работ, техн). Обычные сообщения — `"kind": "news"`.

Когда приходит новое сообщение, рядом с кнопкой всплывает окно с заголовком и текстом. Нажатие на него открывает вкладку «Новости». Повторно то же сообщение не всплывает. Метка на кнопке остаётся, пока эту вкладку не откроют. Пока лента недоступна, переключение стола продолжается.

Выход есть в меню значка у часов.

## Групповая политика

Политика перенаправления папки при входе и при обновлении политики снова записывает сетевой путь. Он может быть разным. Пока связи нет, монитор возвращает локальный путь следующим циклом и запоминает UNC, который только что записала политика. Когда сеть восстановлена, программа возвращает этот путь.

Сценарий входа, который сам записывает UNC в реестр, при обрыве тоже может вернуть сетевой путь. Монитор в автозагрузке после двух неудачных проверок переключит стол обратно.

## Удаление

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall-DesktopSwitch.ps1
```

Для общей автозагрузки добавьте `-AllUsers`. Удаляются ярлык автозапуска и задача планировщика. Журнал и локальные копии ярлыков остаются. Ключ `-InstallDir` дополнительно удаляет папку программы вместе с `config.json`. Если в момент удаления был включён локальный стол, сетевой путь сам не вернётся: запустите монитор при рабочей сети или запишите UNC обратно.

## Ограничения

Программа меняет рабочий стол только того пользователя, в чьём сеансе она запущена. На общем компьютере нужен автозапуск у каждого пользователя либо установка с `-AllUsers`.

Копируются файлы верхнего уровня с расширениями из `SyncExtensions`. Вложенные папки и документы не копируются. Удалённый с общей папки ярлык в локальной копии остаётся до ручной очистки. Обратно на общую папку ничего не записывается.

Локальный путь не должен быть корнем диска, файлом или ссылкой на другую папку. В этих случаях программа оставляет текущий рабочий стол и пишет причину в журнал.

Если AppLocker или политика выполнения запрещают скрипты, для `DesktopSwitch.ps1` нужно отдельное разрешение. Запуск идёт с `-ExecutionPolicy Bypass` и не меняет политику компьютера.
