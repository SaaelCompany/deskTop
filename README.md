# Переключение рабочего стола при потере сети

Программа для Windows следит за доступом в интернет и за общей папкой рабочего стола. Когда связь пропадает, папка «Рабочий стол» текущего пользователя переключается на локальный диск. Когда связь возвращается, снова включается сетевой путь.

Пока сеть есть, ярлыки (`.lnk` и `.url`) копируются с общей папки в локальную. После переключения на столе остаются эти копии.

## Когда это нужно

Общий рабочий стол в домене обычно задан перенаправлением папки: у пользователя в профиле записан путь вида `\\сервер\общая\Desktop`. Проводник читает ярлыки прямо с сервера. Если сервер или интернет недоступны, ярлыки исчезают. У Windows нет запасного локального пути. Эта программа подставляет его сама.

Путь хранится в профиле пользователя (`HKCU`), в значении `Desktop` раздела `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders`. Если перенаправление уже создало значение `{B4BFCC3A-DB2C-424C-B029-7FE99A87C641}`, обновляется и оно. Запускайте программу в сеансе этого пользователя: служба от имени SYSTEM пишет в другой профиль, и стол не меняется.

Обычному пользователю права администратора не нужны. Политика сама записывает сетевой путь, и у разных пользователей он может отличаться. `NetworkDesktopPath` оставьте пустым: программа читает путь из профиля. Пока стол сетевой, берётся текущий UNC. После переключения на локальную папку запоминается последний путь политики, чтобы вернуть именно его. Если политика сменит путь, следующее открытие сетевого стола подхватит новый UNC. Явный UNC в `config.json` нужен только когда путь надо зафиксировать.

## Что происходит при сбое

1. Каждые 15 секунд проверяется интернет и общая папка.
2. Две проверки подряд без связи переключают рабочий стол на локальную папку и перезапускают Проводник. Окна Проводника закрываются, остальные программы остаются.
3. Три успешные проверки подряд возвращают сетевой путь.
4. Если групповая политика во время сбоя снова записывает сетевой путь, программа возвращает локальный.
5. Появляется уведомление. Файлы, созданные на локальном столе во время сбоя, остаются в локальной папке этого компьютера.

По умолчанию переключение срабатывает, если нет интернета или недоступна общая папка (`Trigger` = `InternetOrShare`). Локальный стол включается и тогда, когда файловый сервер недоступен, а проверка интернета ещё отвечает. В `config.json` можно выбрать другое условие:

| Trigger | Когда включается локальный стол |
| --- | --- |
| `InternetOrShare` | Нет интернета или недоступна общая папка |
| `Internet` | Только когда нет интернета |
| `Share` | Только когда недоступна общая папка |

Проверка интернета состоит из двух частей. Сначала программа спрашивает статус сети Windows. Если Windows не видит интернет, выполняется HTTP-запрос (по умолчанию `http://www.msftconnecttest.com/connecttest.txt`) через системный прокси — это нужно в сетях, где статус Windows ошибочно показывает «нет интернета». Общая папка проверяется подключением к порту 445 сервера и чтением каталога. Зависшее обращение к шаре не блокирует следующие циклы.

## Установка

Нужны Windows 10, Windows 11 или Windows Server с рабочим столом и Windows PowerShell 5.1. Установка в автозагрузку текущего пользователя прав администратора не требует.

Администратор один раз кладёт папку на локальный диск, например в `C:\Tools\DesktopSwitch`, и даёт пользователям чтение. Пользователь запускает установщик у себя. Если оставить программу на той же шаре, что и рабочий стол, при обрыве сети она не запустится.

```powershell
cd C:\Tools\DesktopSwitch
copy config.example.json config.json
notepad config.json
```

В `config.json`:

- `Enabled` — `true`.
- `NetworkDesktopPath` оставьте пустым, чтобы следовать политике.
- `Widget.JiraBaseUrl` — адрес Jira Server или Data Center, например `https://jira.company.local`. Для Jira 8.21 и Jira Service Management 4.21 форма заявки берёт проекты helpdesk и создаёт запрос сама. Если это поле заполнено, `ServiceDeskApiUrl` для формы не используется.
- `Widget.ServiceDeskApiUrl` — запасной адрес, куда виджет отправляет заявку методом POST, если Jira не задана.
- `Widget.ServiceDeskUrl` — страница портала. Если пусто, а Jira задана, открывается клиентский портал Jira. Если адрес API и Jira пусты, вкладка «Заявка» открывает эту страницу.
- `Widget.NewsUrl` — лента новостей и технических работ, JSON или RSS. Новости по-прежнему берутся только из этого адреса.
- `LocalDesktopPath` можно не менять. По умолчанию это `%LOCALAPPDATA%\DesktopSwitch\LocalDesktop`, отдельная папка. Так программа не попадает в junction, которым перенаправление иногда подменяет `%USERPROFILE%\Desktop`.

Узнать текущий сетевой путь, пока стол ещё открывается:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\DesktopSwitch.ps1 -Status
```

Перед включением можно посмотреть решение без записи в реестр:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\DesktopSwitch.ps1 -Once -WhatIf
```

Автозагрузка текущего пользователя, без повышения прав:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-DesktopSwitch.ps1
```

Общая автозагрузка всего компьютера требует администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-DesktopSwitch.ps1 -AllUsers
```

Установщик кладёт `DesktopSwitch.vbs` в автозагрузку, останавливает старый монитор и запускает новый. Ключ `-ScheduledTask` дополнительно создаёт задачу на вход пользователя. Повторный запуск установщика применяет изменённый `config.json`.

Журнал каждого пользователя: `%LOCALAPPDATA%\DesktopSwitch\desktop-switch.log`. Двойной щелчок по `Show-DesktopSwitchStatus.cmd` показывает текущее состояние.

## Полезные параметры

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `CheckIntervalSeconds` | 15 | Пауза между проверками. Меньше 5 секунд программа поднимет до 5 |
| `FailuresBeforeSwitch` | 2 | Сколько сбоев подряд нужно для перехода на локальный стол |
| `SuccessesBeforeRestore` | 3 | Сколько успешных проверок подряд нужно, чтобы вернуть сетевой стол |
| `RestoreWhenOnline` | true | Возвращать сетевой путь после восстановления связи |
| `RestartExplorer` | true | Перезапускать Проводник, иначе новый путь виден только после повторного входа |
| `NotifyUser` | true | Показывать уведомление о смене стола, новостях и работах |
| `Widget.Enabled` | true | Круглая кнопка в углу экрана. `false` оставляет только фоновый монитор |
| `Widget.NewsPollMinutes` | 10 | Как часто забирать ленту |
| `Widget.Corner` | BottomRight | Угол: BottomRight, BottomLeft, TopRight, TopLeft |
| `SyncShortcutsWhileOnline` | true | Копировать ярлыки с общей папки в локальную |
| `SyncExtensions` | `.lnk`, `.url` | Какие файлы копировать. Остальные файлы общей папки не копируются |
| `InternetCheck.ProbeUrls` | адрес проверки связи Microsoft | Свои адреса, например `https://intranet.company.local/health` |
| `InternetCheck.ExpectedProbeBody` | `Microsoft Connect Test` | Начало ответа. Для своего адреса очистите строку: тогда достаточно ответа 200 |
| `InternetCheck.UseWindowsConnectivity` | true | Учитывать статус сети Windows |

Если проверка не дала определённого ответа, режим не меняется, а счётчики успешных и неуспешных проверок сбрасываются.

## Кнопка поддержки

В углу экрана остаётся круглая кнопка, как чат на сайте. По нажатию над ней открывается компактное окно. Сначала открыта вкладка «Заявка». Повторное нажатие, стрелка в шапке окна или Escape сворачивают его и не останавливают программу. Переключение стола от кнопки не зависит и происходит само.

Вкладка «Заявка» — форма в техническую поддержку. Логин Windows (`ДОМЕН\пользователь`) и имя компьютера подставляются сами из текущего сеанса, поля только для чтения. В шапке окна они тоже видны. Если в адресе портала есть подстановки `{login}` и `{computer}`, они заменяются на эти значения.

Для Jira Server 8.21 и Jira Service Management 4.21.1 укажите `Widget.JiraBaseUrl` без хвоста вроде `/browse`. Это адрес сервера, не Jira Cloud. При открытии вкладки программа запрашивает `GET /rest/servicedeskapi/servicedesk` и показывает проекты helpdesk, которые эта учётная запись видит. После выбора проекта загружаются типы запросов. Кнопка «Отправить» создаёт клиентский запрос `POST /rest/servicedeskapi/request` с темой, описанием, номером проекта и типом. В описание дописываются логин Windows и имя компьютера. В случае успеха в окне появляется ключ заявки, например `ITHD-12`. Ссылка «Открыть портал» ведёт на `/servicedesk/customer/portals`, если свой адрес портала не задан.

Вход в Jira: пустой `Widget.ServiceDeskToken` означает проверку Windows (Negotiate/NTLM) текущей учётной записи. Заявка создаётся от того пользователя Jira, под которым прошла эта проверка. Если Jira не принимает вход Windows, в `ServiceDeskToken` кладётся личный токен доступа (PAT, Jira 8.14 и новее). Пароль пользователя программа не хранит. Токен в общем `config.json` — это ключ одной учётной записи Jira, поэтому папку лучше оставить пользователям только для чтения. Логин Windows при этом всё равно попадает в текст заявки: он часто не совпадает с именем в Jira.

Если `JiraBaseUrl` пуст, остаётся прежняя отправка: POST JSON с полями `subject`, `body`, `category`, `user`, `computer`, `createdAt` на `Widget.ServiceDeskApiUrl`. Категория тогда выбирается из списка «Инцидент», «Запрос обслуживания», «Вопрос». Если задан только адрес портала, кнопка отправки открывает его.

Вкладка «Новости» показывает ленту. Технические работы отмечены оранжевым, обычные новости — синим. Лента — JSON, как в `examples/news.json`, либо RSS. У технических работ `"kind": "maintenance"` (или категория RSS со словом maintenance, работ, техн). Обычные сообщения — `"kind": "news"`.

Когда приходит новое сообщение, рядом с кнопкой всплывает окно с заголовком и текстом. Нажатие на него открывает вкладку «Новости». Повторно то же сообщение не всплывает. Красная метка на кнопке остаётся, пока эту вкладку не откроют. Пока лента недоступна, переключение стола продолжается.

Выход есть в меню значка у часов.

## Групповая политика

Политика перенаправления папки при входе и при обновлении политики снова записывает сетевой путь. Он может быть разным. Пока связи нет, монитор возвращает локальный путь следующим циклом и запоминает UNC, который только что записала политика. Когда сеть восстановлена, программа возвращает этот путь.

Сценарий входа, который сам записывает UNC в реестр, при обрыве тоже может вернуть сетевой путь. Монитор в автозагрузке после двух неудачных проверок переключит стол обратно.

## Удаление

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall-DesktopSwitch.ps1
```

Для общей автозагрузки добавьте `-AllUsers`. Удаляются ярлык автозапуска и задача планировщика. `config.json`, журнал и локальные копии ярлыков остаются. Если в момент удаления был включён локальный стол, сетевой путь сам не вернётся: запустите монитор при рабочей сети или запишите UNC обратно.

## Ограничения

Программа меняет рабочий стол только того пользователя, в чьём сеансе она запущена. На общем компьютере нужен автозапуск у каждого пользователя либо установка с `-AllUsers`.

Копируются файлы верхнего уровня с расширениями из `SyncExtensions`. Вложенные папки и документы не копируются. Удалённый с общей папки ярлык в локальной копии остаётся до ручной очистки. Обратно на общую папку ничего не записывается.

Локальный путь не должен быть корнем диска, файлом или ссылкой на другую папку. В этих случаях программа оставляет текущий рабочий стол и пишет причину в журнал.

Если AppLocker или политика выполнения запрещают скрипты, для `DesktopSwitch.ps1` нужно отдельное разрешение. Запуск идёт с `-ExecutionPolicy Bypass` и не меняет политику компьютера.
